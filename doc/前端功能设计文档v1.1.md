# 前端功能设计文档

## 文档基础信息

1. 文档版本：V1.0
2. 项目名称：本地AI音乐推荐客户端
3. 编写目的：定义客户端全部前端页面、交互逻辑、业务流程、数据结构，作为前端开发、前后端接口联调依据
4. 核心约束：本项目无虚拟桌宠、DJ角色、TTS语音播报、Live2D动画相关功能，仅实现**账号配置、歌单管理、AI用户画像、AI对话交互、本地音乐播放器**五大核心能力
5. 通信方案：HTTP接口处理一次性配置/查询操作；WebSocket长连接承载AI对话、播放器实时控制双向交互

## 一、术语与名词定义

1. UserProfits：用户画像数据表，分为「手动维护基础信息」和「AI自动生成音乐偏好画像」两部分
2. APIKey：大模型、音乐第三方服务密钥，用于后端调用LLM、网易云接口
3. WebSocket：前后端实时双向通信通道，用于AI聊天、播放指令实时推送
4. Playlist：网易云导入歌单，通过分享链接拉取本地持久化存储
5. operation：后端下发操作指令标识，用于前端执行播放、切歌、添加歌单等播放器行为

## 二、系统整体启动流程

1. 客户端程序打开，前端发起HTTP初始化接口`/api/init`，一次性拉取系统配置、网易云登录状态、用户画像、本地全部歌单、当前播放列表与播放状态；
2. 初始化数据加载完成后，建立WebSocket长连接`ws://localhost:8000/ws/client`；
3. WebSocket连接成功后进入可交互状态，前端每30s发送心跳包维持连接，断线自动周期性重连；
4. 所有一次性配置、数据增删改操作使用HTTP接口；实时对话、播放控制全部通过WebSocket传输。

## 三、四大核心功能模块详细设计

### 模块1：系统设置功能模块

模块包含两大子功能：API密钥配置、网易云账号登录管理，页面独立设置面板展示。

#### 1.1 APIKey设置功能

1. 功能描述：提供输入框，配置LLM大模型密钥、网易云第三方服务密钥；
2. 交互逻辑：
   - 打开设置页自动加载已保存密钥；
   - 用户修改密钥后点击保存，调用PUT接口更新配置；
   - 密钥为空/格式错误时前端给出表单校验提示；
3. 约束：未配置LLM APIKey时，AI对话、歌单画像分析功能全部禁用并弹窗提示。

#### 1.2 网易云账号登录功能

1. 功能描述：完成网易云账号授权登录，后端可拉取歌单、获取播放资源链接；
2. 交互逻辑：
   - 设置面板展示登录状态：未登录/已登录+用户昵称；
   - 未登录状态展示登录入口，支持扫码/验证码登录；
   - 登录成功后刷新页面状态，自动拉取登录用户基础信息；
3. 约束：未登录网易云账号时，歌单导入、音乐播放功能禁用。

### 模块2：AI画像与歌单管理模块

核心能力：歌单导入、歌单全量CRUD、AI自动分析生成用户音乐画像、UserProfits信息维护。

#### 2.1 歌单导入功能

1. 功能描述：用户粘贴网易云歌单分享链接，一键导入完整歌单至本地存储；
2. 交互流程：
   1. 用户在歌单管理页面粘贴歌单链接，点击导入按钮；
   2. 前端调用导入接口，后端拉取歌单所有歌曲数据并本地持久化；
   3. 歌单导入完成后，**自动触发AI画像分析任务**，更新UserProfits音乐偏好；
3. 异常处理：链接非法、歌单不存在、无权限访问时前端展示错误提示。

#### 2.2 歌单增、删、查、改管理

1. 查询：页面展示全部本地导入歌单列表，点击歌单可查看内部所有歌曲；
2. 修改：仅支持修改歌单本地备注、自定义名称，不修改源链接与歌曲数据；
3. 删除：删除指定歌单，本地缓存歌曲同步清除，删除后自动重新执行AI画像分析更新用户偏好；
4. 新增：仅支持通过链接导入方式新增歌单，不支持手动自建空白歌单。

#### 2.3 AI画像自动分析功能

1. 功能描述：后端读取本地所有导入歌单歌曲信息，调用LLM分析用户长期听歌偏好，自动生成完整音乐画像，存入UserProfits；
2. 触发时机：
   - 导入新歌单完成自动触发；
   - 删除歌单完成自动触发；
   - 用户手动点击「重新分析画像」按钮主动触发；
3. 约束：**音乐偏好画像仅由AI自动生成更新，前端无手动编辑入口**。

#### 2.4 UserProfits 用户画像维护

UserProfits分为两类数据，权限区分明确：

1. 可手动修改（前端提供编辑面板）：用户昵称、头像图片链接；
2. 仅AI自动生成、禁止手动修改：喜爱曲风、喜爱歌手、排斥曲风、整体听歌偏好描述、画像最后更新时间；
3. 页面展示：独立画像面板，完整展示用户基础信息与AI分析得出的音乐偏好。

### 模块3：AI Chat对话交互模块

采用WebSocket双向实时通信，统一交互入口，前端仅发送文本内容，后端统一完成意图识别，返回标准化三段核心数据`text、url、operation`。

#### 3.1 支持交互场景

1. 歌曲推荐：根据用户画像、指定风格从本地歌单筛选歌曲；
2. 日常闲聊对话：简单情绪陪伴、文字问答；
3. 歌曲介绍：查询当前播放歌曲/指定歌曲的简介、创作背景；
4. 播放列表操作：切歌、添加歌曲至播放列表、清空队列等指令。

#### 3.2 前端交互规则

1. 消息发送方式：两种输入来源统一封装为同一种WebSocket消息：
   - 手动文字输入框发送；
   - 麦克风语音识别转文字后发送；
2. 前端仅传递纯文本内容，无需区分操作类型，全部意图识别逻辑交由后端Agent处理；
3. 消息展示：聊天面板区分用户消息、AI回复消息，实时渲染对话记录。

#### 3.3 后端返回数据处理规则

后端每条AI回复固定携带3个核心字段，前端分别处理：

1. text：AI回复文字、歌曲介绍文案，直接渲染在聊天窗口；
2. url：歌曲播放链接、歌曲封面图片地址，播放器/封面组件读取使用；
3. operation：操作指令标识，前端根据标识执行对应播放器逻辑，可选值：
   - `recommend`：推荐歌曲，展示推荐列表；
   - `play_song`：自动播放指定歌曲；
   - `skip_song`：执行切歌；
   - `add_playlist`：将歌曲加入播放队列；
   - `song_intro`：仅展示歌曲介绍，无播放动作。

### 模块4：本地音乐播放器模块

独立播放器组件，负责音频播放控制、本地播放列表维护，接收WebSocket下发的播放指令。

#### 4.1 基础播放控制功能

1. 根据后端下发的歌曲播放URL加载音频资源；
2. 基础操作：播放、暂停、切换下一首/上一首；
3. 播放状态同步：播放开始、播放结束、暂停时主动上报状态给后端WebSocket。

#### 4.2 播放列表管理

1. 前端本地维护全局播放列表，实时展示队列内所有歌曲；
2. 接收后端`music.update_playlist`消息同步更新队列；
3. 支持手动清空队列、移除单首歌曲、调整歌曲顺序。

## 四、全局标准数据结构定义

### 4.1 UserProfits 用户画像

```typescript
interface UserProfits {
  // 前端手动维护基础信息
  nickname: string;
  avatar_url?: string;
  // AI自动生成音乐偏好（不可手动编辑）
  favorite_genres: string[];
  favorite_artists: string[];
  disliked_genres: string[];
  music_preference_desc: string;
  update_at: number; // 画像AI更新毫秒时间戳
}
```

### 4.2 Playlist 歌单

```typescript
interface Playlist {
  playlist_id: string;
  name: string; // 本地自定义名称
  source_url: string; // 原始网易云分享链接
  song_count: number; // 歌单歌曲总数
  created_at: number;
}
```

### 4.3 Song 歌曲基础结构

```typescript
interface Song {
  id: string;
  name: string;
  artists: Artist[];
  album: Album;
  duration_ms: number;
  cover_url?: string; // 歌曲封面图链接
}
interface Artist {
  id: string;
  name: string;
}
interface Album {
  id: string;
  name: string;
}
```

### 4.4 用户歌曲反馈数据结构

```typescript
interface SongFeedback {
  song_id: string;
  action: "like" | "dislike" | "favorite" | "skip";
  ts: number;
}
```

## 五、核心业务完整交互流程

### 流程1：歌单导入+AI自动画像更新

1. 用户粘贴歌单链接，点击导入；
2. 前端调用HTTP导入接口，后端拉取歌单歌曲并本地存储；
3. 接口返回导入成功标识，前端自动发起AI画像分析请求；
4. 后端完成全歌单分析，覆盖更新UserProfits偏好数据；
5. 前端刷新用户画像面板，展示最新分析结果。

### 流程2：AI Chat 完整对话交互

1. 用户输入文字/语音转文字，前端发送`chat.user_text`WebSocket消息；
2. 后端Agent完成意图识别、任务规划，生成回复内容与操作指令；
3. 后端推送`chat.reply`消息，携带text、url、operation字段；
4. 前端渲染对话文本，根据operation执行对应播放器逻辑（播放/切歌/展示介绍）；
5. 若涉及歌曲播放，后端同步下发`music.play`消息推送歌曲完整资源。

### 流程3：程序初始化加载流程

1. 客户端启动，调用`GET /api/init`一次性拉取全量初始化数据；
2. 渲染设置页面、歌单列表、用户画像、播放器队列；
3. 初始化数据加载完成，建立WebSocket长连接；
4. 监听WebSocket消息，等待用户发起AI对话、播放操作。

## 六、异常与容错处理方案

1. **APIKey未配置**：进入AI对话、歌单分析页面弹窗提示跳转设置面板；
2. **网易云账号未登录**：导入歌单、播放歌曲功能按钮置灰，弹窗引导登录；
3. **LLM大模型调用失败**：AI对话返回错误提示，画像分析弹窗提示密钥有效性；
4. **音乐资源获取失败**：歌曲播放失败，前端弹窗提示歌曲资源失效，自动切换下一首；
5. **WebSocket断线**：前端开启自动重连定时器，重连期间禁用AI对话功能，重连成功恢复交互；
6. **歌单链接失效/无权限**：导入接口返回错误码，前端展示文案提示更换有效歌单链接。

## 七、前后端通信对接说明

1. 一次性查询、配置、数据操作：全部使用HTTP接口，统一前缀`/api/`；
2. 实时对话、播放控制、状态推送：统一使用WebSocket长连接；
3. 所有HTTP接口返回标准格式：`{code: number, msg: string, data: any}`，code=0代表成功；
4. WebSocket所有消息统一JSON结构，依靠`type+subtype`区分业务类型；
5. 心跳机制：前端每30s发送ping包，服务端返回pong包维持连接。
